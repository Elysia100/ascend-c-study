# 环境搭建与踩坑记录

环境：GitCode Notebook（Ubuntu 22.04 aarch64 容器）+ Ascend 910B4
CANN：由预装的 8.5.0 升级到 9.2.0-beta.2，装在 `/opt/atomgit/Ascend/cann-9.2.0-beta.2`

---

## 坑一：`undefined symbol` —— 环境版本混用

**现象**：`bash build.sh` 报

```
using ASCEND_HOME_PATH: /usr/local/Ascend/cann-8.5.0
opbuild ops error: /opt/atomgit/Ascend/cann/tools/opbuild/op_build:
  symbol lookup error: undefined symbol: _ZN3ops10OpParamDef16GetInitValueListEv
```

**符号解码**：

```
_ZN 3ops 10OpParamDef 16GetInitValueList Ev
     ↓         ↓              ↓          ↓
   ops::  OpParamDef::  GetInitValueList ()
```

**根因**：三套东西版本不一致——

| 组件 | 来源 | 版本 |
|---|---|---|
| CMake 模块 | `ASCEND_HOME_PATH` | 8.5.0（旧） |
| `op_build` 工具 | `ASCEND_CANN_PACKAGE_PATH` | 9.2.0（新） |
| 运行时库 | `LD_LIBRARY_PATH` | 8.5.0（旧） |

新版 `op_build` 需要新版 `libopmaster.so` 里的符号，但运行时加载到的是旧版库。

**解法**：

```bash
source /opt/atomgit/Ascend/cann-9.2.0-beta.2/set_env.sh   # 整套 source
rm -rf build_out                                          # 必须删，CMake 会缓存旧路径
bash build.sh
```

> 关键点：**只改 CMakePresets.json 不清 CMake 缓存是无效的**——路径早已被缓存进 `build_out/`。

## 坑二：CANN 路径填的是软链接，不是真实目录

`/opt/atomgit/Ascend/cann` 只是 `set_env.sh` 的入口软链接，真实安装目录是带版本号的
`/opt/atomgit/Ascend/cann-9.2.0-beta.2`。

**判断方法**：看环境变量，不要猜。

```bash
printenv | grep -i ascend
# ASCEND_HOME_PATH=/opt/atomgit/Ascend/cann-9.2.0-beta.2
```

## 坑三：`run.sh` 会自动选中旧版 CANN

`AclNNInvocation/run.sh` 里：

```bash
if [ ! $ASCEND_HOME_DIR ]; then
    if [ -d "$HOME/Ascend/ascend-toolkit/latest" ]; then
        export ASCEND_HOME_DIR=$HOME/Ascend/ascend-toolkit/latest
    else
        export ASCEND_HOME_DIR=/usr/local/Ascend/ascend-toolkit/latest   # ← 旧版
    fi
fi
```

两个候选路径都不是 9.2 的安装位置，于是 fallback 到旧的 8.5.0。

**解法**：显式指定，跳过自动选择。

```bash
ASCEND_HOME_DIR=/opt/atomgit/Ascend/cann-9.2.0-beta.2 bash run.sh
```

> 注意：`AclNNInvocation` 属测试工程，按要求不可修改，所以只能从环境侧绕。

## 环境变量污染的处理

source 新版的 `set_env.sh` 只是把新路径**追加**到各搜索路径前面，旧路径仍在后面：

```
LD_LIBRARY_PATH=/opt/atomgit/Ascend/cann-9.2.0-beta.2/lib64:...:/usr/local/Ascend/cann-8.5.0/lib64:...
```

由于按顺序查找，新版优先命中，所以可用。但要确认 `ASCEND_HOME_PATH` 已经是新版——
它决定 CMake 模块从哪来。

每次登录都要 source 一次，可写入 `~/.bashrc`：

```bash
echo 'source /opt/atomgit/Ascend/cann-9.2.0-beta.2/set_env.sh' >> ~/.bashrc
```

## 排查方法论

这次最值得记的一点：**报错的表象和真实原因可能完全无关。**

`undefined symbol` 看起来像"代码写错了"，实际是环境问题。定位靠三步：

1. **解码符号名** —— `c++filt _ZN3ops10OpParamDef16GetInitValueListEv` 或手工拆解，看它属于哪个库
2. **对比路径来源** —— 把报错里的路径与 `printenv | grep -i ascend` 对照，看是不是同一版本
3. **查工具自身的依赖** —— `ldd <工具路径> | grep <关键库>` 能直接看出加载了哪个版本

顺序很重要：**先确认环境自洽，再怀疑代码。**
