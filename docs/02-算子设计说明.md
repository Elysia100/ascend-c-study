# TanhCustom 算子设计说明

## 一、Tiling 参数怎么来的

```
BLOCK_DIM  = 8      使用的核数
TILE_NUM   = 8      每核切分块数
BUFFER_NUM = 2      双缓冲队列深度
```

kernel 侧的计算链：

```
blockLength = totalLength / GetBlockNum()          = 16384 / 8 = 2048
tileLength  = blockLength / tileNum / BUFFER_NUM   = 2048 / 8 / 2 = 128
loopCount   = tileNum * BUFFER_NUM                 = 16
```

**自洽性校验**：`loopCount × tileLength = 16 × 128 = 2048 = blockLength` ✓
即每核循环 16 次，正好覆盖它负责的全部 2048 个元素，不多不少。

**为什么要除以 BUFFER_NUM**：`Process()` 的循环次数是 `tileNum * BUFFER_NUM`，
不是 `tileNum`。如果不除，单核搬运的总量会变成 `blockLength * BUFFER_NUM`，越界。

## 二、为什么必须用 fp32 算中间量

这是本算子最关键的一处设计。

`float16` 只有 10 位尾数，在 `x ≈ 1` 附近的分辨率约 `2^-10 ≈ 9.77e-4`。

若直接在半精度下计算 `e^x - e^-x`：

- `e^x` 和 `e^-x` 会被各自舍入到最近的 fp16 值
- 当 `x` 较小时，两者数值接近，相减后**有效位大量抵消**
- 极端情况下两个已舍入成同一个数，相减直接得到 **0**

而更麻烦的是：这种抵消带来的**绝对误差本身很小**，`1e-3` 的容差判据几乎抓不住它——
结果就是"测试通过但算子是错的"。

因此 kernel 先把输入 `Cast` 到 `float32`，全程在 fp32 下算完，最后再收窄回 fp16：

```cpp
AscendC::Cast(tmp0, xLocal, AscendC::RoundMode::CAST_NONE, tileLength);  // fp16 -> fp32
AscendC::Exp(tmp1, tmp0, tileLength);                                    // e^x
AscendC::Muls(tmp2, tmp0, static_cast<float>(-1.0), tileLength);         // -x
AscendC::Exp(tmp2, tmp2, tileLength);                                    // e^-x
AscendC::Sub(tmp0, tmp1, tmp2, tileLength);                              // e^x - e^-x
AscendC::Add(tmp1, tmp1, tmp2, tileLength);                              // e^x + e^-x
AscendC::Div(tmp2, tmp0, tmp1, tileLength);                              // tanh(x)
AscendC::Cast(yLocal, tmp2, AscendC::RoundMode::CAST_RINT, tileLength);  // fp32 -> fp16
```

为此 `Init()` 里额外申请了三块 fp32 临时 buffer（各 `tileLength * sizeof(float)`）。

## 三、为什么收窄用 CAST_RINT

`CAST_RINT` = IEEE754 round-to-nearest-even（就近舍入，平局取偶）。

选它是因为与 numpy 的 `astype(np.float16)` 行为一致——而精度比对的真值
（`golden.bin`）正是 numpy 生成的。**舍入方式不对齐，会在无意义的地方产生误差**，
干扰对真实实现质量的判断。

## 四、Tiling 数据如何传给 kernel

`tanh_custom_tiling.h` 里用的是**普通 POD 结构体**，不是 `BEGIN_TILING_DATA_DEF` 宏：

```cpp
struct TanhCustomTilingData {
    uint32_t totalLength;
    uint32_t tileNum;
};
```

好处是 host 侧可以直接取指针写字段，**不需要 `SaveToBuffer` / `memcpy`**：

```cpp
TanhCustomTilingData* tiling = context->GetTilingData<TanhCustomTilingData>();
tiling->totalLength = static_cast<uint32_t>(context->GetInputShape(0)->GetOriginShape().GetShapeSize());
tiling->tileNum = TILE_NUM;
context->SetBlockDim(BLOCK_DIM);
```

kernel 侧用 `GET_TILING_DATA` 取出：

```cpp
REGISTER_TILING_DEFAULT(TanhCustomTilingData);
GET_TILING_DATA(tilingData, tiling);
op.Init(x, y, tilingData.totalLength, tilingData.tileNum);
```

## 五、移植注意事项

1. **`GetBlockIdx` / `GetBlockNum` 需要 `AscendC::` 限定** —— CANN 9.0.0 起这两个函数
   位于 `AscendC` 命名空间内，不加限定直接编译失败
2. **`CMakePresets.json` 的 `ASCEND_CANN_PACKAGE_PATH`** 必须指向真实安装目录，
   `build.sh` 走 `cmake --preset=default`，命令行覆盖不了
3. **整套 `source set_env.sh`**，不要逐变量覆盖（见 `01-环境搭建与踩坑.md`）
4. **改完配置必须 `rm -rf build_out`**，否则 CMake 缓存里的旧路径继续生效
